# 算术编码深度解析

算术编码把**整条消息**映射到一个半开区间，而不是为每个符号分配整数比特的码字。平均码长可以逼近信息熵，而不受 Huffman「每个符号至少 1 比特」的限制。

## 核心思想

设符号 $s$ 的概率为 $p_s$，累积概率为 $F(s)=\sum_{t<s}p_t$。当前区间为 $[low, high)$ 时，编码 $s$ 将其收缩为：

$$
[low + (high-low)F(s),\quad low + (high-low)F(s+p_s))
$$

消息越长，最终区间越窄，表示该区间所需的比特数约为 $-\log_2(high-low)$，因此 $L \approx H + \varepsilon$。

::: tip 实现与教材伪代码
教材常用浮点 $[0,1)$ 演示。CompressKit 使用固定宽度整数、缩放频率表和位级重归一化，避免浮点精度耗尽。见 [算术编码算法页](/algorithms/arithmetic)。
:::

## 本仓库的工程选择

- **静态模型**：先扫描全文得到 256 字节频率，再加 EOF 符号，编码期间不再更新。
- **频率缩放**：总和限制在 $2^{24}$，保证 `range / total` 不会把子区间压成 0。
- **EOF**：解码器读到 EOF 符号后停止，不依赖外部长度字段。
- **格式**：`AEN2` + 小端频率表 + 比特流 + CRC-32。v1 magic `AENC` 被明确拒绝。

## 与 Huffman 的差别

| | Huffman | Arithmetic |
|--|---------|------------|
| 码字 | 每个符号整数比特 | 整条消息共享一个区间 |
| 理论 | $H \le L < H+1$ | $L \approx H+\varepsilon$ |
| 本实现 I/O | 位 | 位（重归一化） |
| 适用 | 教学前缀码、速度 | 对比「更接近熵」的收益 |

偏斜分布上两者压缩率接近；接近均匀的分布上算术编码的优势更明显，但本实现仍要为频率表付出约 1 KiB 固定开销。

## 诊断

```bash
make stats
```

`tests/lab_stats.py` 会打印输入的 Shannon 熵（比特/字节），以及各算法压缩后的实际比特/字节。算术编码的「vs entropy」列通常小于 Huffman，但仍大于 0，因为有表头、EOF 与字节对齐。
