# 区间编码深度解析

区间编码（Range Coder）是算术编码的**整数、字节输出**变体。它维护半开区间 `[low, low+range)`，在 `range` 足够窄或顶字节已确定时输出一个字节并左移状态。压缩率与算术编码接近，I/O 以字节为单位。

## 精度下限

编码器必须保持 `range >= 2^{24}`（与频率表总和上限相同）。若只在「`low` 与 `low+range` 的顶字节相同」时才移位，窄区间跨过字节边界时 `range` 会塌缩，子区间宽度变成 0，**在接近不可压缩的数据上静默丢数据**。本仓库的循环同时检查精度下限，并在跨越边界时把区间端点对齐后再输出。

这是 v2 相对早期 RCNC 流的行为修复；那些旧 payload 不能用当前解码器恢复。

## 本仓库的工程选择

- 32 位状态，每次重归一化输出 1 字节。
- 与算术编码共享 `frequency_table`：静态模型、EOF、缩放到 $2^{24}$。
- 解码用二分查找定位符号（累积频率表长度 258），复杂度 $O(n\log \sigma)$ 的 $\sigma$ 为常数 257。
- 格式：`RCN2` + 小端频率表 + 字节流 + CRC-32。v1 magic `RCNC` 被拒绝。

## 与算术编码

| | Arithmetic | Range |
|--|------------|-------|
| 状态 | 位级区间 | 字节级 `[low, low+range)` |
| 输出 | 位 | 字节 |
| 模型 | 静态 + EOF | 相同 |
| 教学角色 | 熵编码原理 | 生产里更常见的整数写法 |

两者都不是自适应模型。若要 order-1 / PPM，需要新的格式世代，不能塞进 `RCN2`。

## 性能

当前实现对 10 MiB 语料可以在 CLI smoke 的超时内 round-trip。基准请用 `make bench` 在同一机器上重跑，不要沿用「Range 只能测 8 KiB」的旧快照。

```bash
make bench
make stats
```
